    Flashlight Snowflake Dashboard — Developer Guide

    How to modify KPIs, metrics, charts, and SQL queries in the Snowflake demo dashboard.

    Architecture Overview

    ┌─────────────────────────────────────┐
│  Dashboard UI (NiceGUI + Plotly)    │  src/flashlight/dashboard/views/snowflake_visibility.py
│  - KPI tiles, charts, tables        │  src/flashlight/dashboard/views/hidden_waste.py
│  - Uses chrome.py for styling        │  src/flashlight/dashboard/views/policies.py
└────────────────┬────────────────────┘
                 │ calls data functions
                 ▼
┌─────────────────────────────────────┐
│  Data Layer (DuckDB SQL)            │  src/flashlight/dashboard/snowflake_visibility_data.py
│  - All SQL queries live here         │  (1123 lines, ~40 functions)
│  - Returns pd.DataFrame             │
└────────────────┬────────────────────┘
                 │ queries
                 ▼
┌─────────────────────────────────────┐
│  Parquet Files (synthetic data)     │  FLASHLIGHT_HOME/account_usage/
│  - Auto-loaded as DuckDB tables      │  (19 files, generated by sample.py)
│  - Table name = filename w/o .parquet│
└─────────────────────────────────────┘

    Key principle: To change what the dashboard shows, you modify two layers: 1. The SQL query in the data layer (what data to fetch) 2. The view code in the UI layer (how to display it)

    File Map

    What you want to change Edit this file
    KPI tile values/labels views/snowflake_visibility.py (display) + snowflake_visibility_data.py (data)
    Chart type or appearance views/snowflake_visibility.py (Plotly figure code)
    SQL query logic snowflake_visibility_data.py (the function that returns the data)
    Add new data source src/flashlight/sample.py (add Parquet)
    Governance policies snowflake/src/gov01-gov05*.sql
    Dashboard styling src/flashlight/dashboard/chrome.py
    Navigation/routing src/flashlight/dashboard/router.py

    Modifying KPI Tiles

    Where KPIs are defined

    LeaderBoard KPIs (line ~87 in snowflake_visibility.py): 

    def _executive_summary() -> None:
    kpis = sf_data.kpi_summary()
    ai = sf_data.ai_spend_summary()
    sw = sf_data.hidden_waste_summary()

    chrome.kpi_row([
        (f"Monthly Cost ({kpis['month_label']})", f"${kpis['total_cost']:,.0f}", ...),
        ("AI Spend", f"${ai['ai_cost']:,.0f}", ...),
        ("Storage Cost", f"${kpis['storage_cost']:,.0f}", ...),
        ("Hidden Waste Potential", f"${sw['total']:,.0f}", ...),
        ("Year to Date", f"${kpis['ytd_cost']/1e6:.1f}M", ...),
    ])

    To change a KPI label

    Edit the first element of the tuple (the display name string).

    To change what value a KPI shows

    Edit the data function in snowflake_visibility_data.py. For example, kpi_summary():

    def kpi_summary() -> dict:
    con = _con()
    try:
        # Current month compute cost
        compute = con.execute("""
            SELECT SUM(credits_used) * 4.0 AS cost
            FROM warehouse_metering_history
            WHERE start_time >= DATE_TRUNC('month', CURRENT_DATE)
        """).fetchone()[0] or 0

        # ... more queries for each field
        return {
            "total_cost": compute + serverless + storage,
            "compute_cost": compute,
            "storage_cost": storage,
            "ytd_cost": ytd,
            "month_label": month_label,
        }
    finally:
        con.close()

    To add a new KPI tile

    1. Add a new field to the relevant data function (or create a new function)
    2. Add a new tuple to the chrome.kpi_row([...]) list

    Modifying SQL Queries

    All SQL lives in src/flashlight/dashboard/snowflake_visibility_data.py. Each function follows this pattern:

    def my_metric() -> pd.DataFrame:
    con = _con()       # Opens DuckDB connection with all Parquet tables registered
    try:
        return con.execute("""
            SELECT ...
            FROM table_name    -- table name = parquet filename without .parquet
            WHERE ...
        """).fetchdf()
    finally:
        con.close()

    Available tables (auto-registered from Parquet files)

    Table Name Key Columns
    warehouse_metering_history start_time, warehouse_name, credits_used
    warehouse_load_history start_time, warehouse_name, avg_running, avg_queued_load
    query_history query_id, user_name, warehouse_name, start_time, total_elapsed_time, bytes_scanned, bytes_spilled_*, percentage_scanned_from_cache
    query_attribution_history query_id, warehouse_name, credits_attributed_compute
    storage_usage usage_date, storage_bytes, stage_bytes, failsafe_bytes
    table_storage_metrics table_catalog, table_schema, table_name, active_bytes, time_travel_bytes, failsafe_bytes
    tag_references object_name, domain, tag_name, tag_value
    warehouse_events_history timestamp, warehouse_name, event_name, event_reason
    metering_history start_time, service_type, name, credits_used
    metering_daily_history usage_date, service_type, credits_used
    hidden_waste_compute warehouse_name, waste_type, actual_cost_usd, wasted_cost_usd
    hidden_waste_storage object_name, waste_type, size_gb, monthly_cost_usd
    hidden_waste_ai waste_pattern, function_name, model_name, wasted_cost_usd

    Example: Change credit price

    Currently hardcoded as * 4.0 (or * 4) in SQL. To change: 

    -- Find and replace all occurrences of:
SUM(credits_used) * 4.0 AS cost
-- Change 4.0 to your credit price

    Or define a constant at the top of the data file.

    Modifying Charts

    Charts use Plotly via NiceGUI. Pattern:

    import plotly.graph_objects as go

fig = go.Figure()
fig.add_trace(go.Bar(x=df["name"], y=df["cost"], name="Cost"))
chrome.style_fig(fig, height=400, has_legend=True, currency_axis="y")
chrome.plot(fig)

    Common chart modifications

    Change How
    Chart height chrome.style_fig(fig, height=500)
    Add/remove legend has_legend=True/False
    Y-axis as currency currency_axis="y" adds $ formatting
    Pie chart go.Pie(labels=..., values=..., hole=0.4) for donut
    Stacked bar Multiple go.Bar() traces with barmode="stack"
    Area chart go.Scatter(fill="tozeroy") — but avoid if you need custom y-axis range

    Y-axis range (avoid starting from 0)

    y_min = df["value"].min() * 0.9
y_max = df["value"].max() * 1.1
fig.update_layout(yaxis=dict(range=[y_min, y_max]))

    Modifying Tables

    Tables use NiceGUI's ui.table:

    columns = [
    {"name": "col_id", "label": "Display Name", "field": "col_id", "align": "left"},
]
rows = df.to_dict("records")
ui.table(columns=columns, rows=rows).props("dense flat hide-pagination")

    Common table modifications

    Change How
    Remove search/pagination .props("dense flat hide-pagination")
    Add search .props("dense flat filter")
    Column alignment "align": "left"/"right"/"center"
    Format currency Pre-format in DataFrame: df["cost"] = df["cost"].apply(lambda x: f"${x:,.0f}")

    Adding a New Metric or View

    Step 1: Add the data function

    In snowflake_visibility_data.py: 

    def my_new_metric() -> pd.DataFrame:
    con = _con()
    try:
        return con.execute("""
            SELECT warehouse_name, SUM(credits_used) * 4.0 AS cost
            FROM warehouse_metering_history
            WHERE start_time >= CURRENT_DATE - INTERVAL 30 DAY
            GROUP BY warehouse_name
            ORDER BY cost DESC
            LIMIT 10
        """).fetchdf()
    finally:
        con.close()

    Step 2: Add the UI component

    In the appropriate view function (e.g., _executive_summary() for LeaderBoard): 

    # Add a new panel with chart
data = sf_data.my_new_metric()
if not data.empty:
    with chrome.panel():
        chrome.panel_title("My New Metric")
        fig = go.Figure()
        fig.add_trace(go.Bar(x=data["warehouse_name"], y=data["cost"]))
        chrome.style_fig(fig, height=350, currency_axis="y")
        chrome.plot(fig)

    Step 3: If new data is needed

    If existing Parquet files don't have the columns you need: 1. Add to generate.py or modify an existing generator 2. Regenerate: uv run fl sample 3. The data layer auto-discovers new Parquet files (no registration needed)

    Governance SQL (Policy Checks)

    The 5 governance SQL files in snowflake/src/ can be executed against live Snowflake:

    File Policy Modifiable Threshold
    gov01-*.sql Idle warehouse detection Min credits threshold, avg_running threshold
    gov02-*.sql Tag completeness Required tag list, minimum tag count
    gov03-*.sql Oversized warehouse Max allowed size (e.g., "3X-Large")
    gov04-*.sql Weekend running (dev) Day-of-week filter, min credits
    gov05-*.sql Resource monitor coverage Monitor assignment check

    To modify a governance policy threshold

    Edit the SQL file directly. Example in gov01: 

    -- Change idle threshold from 0.15 to 0.20
WHERE COALESCE(l.avg_running, 0) < 0.20
  AND m.credits_used >= 50  -- Change minimum credits threshold

    To add a new governance policy

    1. Create snowflake/src/gov06-descriptive-name.sql
    2. Use only accessible views: warehouse_metering_history, warehouse_load_history, warehouse_events_history, metering_history, resource_monitors
    3. Do NOT use SNOWFLAKE.ACCOUNT_USAGE.WAREHOUSES (not accessible)
    4. Validate: run via sql_execute with only_compile=true

    Quick Reference: Common Tasks

    I want to... Steps
    Change a KPI value Edit data function in snowflake_visibility_data.py → adjust SQL
    Change a KPI label Edit chrome.kpi_row([(label, ...)]) in the view
    Add a new chart Add data function → add UI code in view → wrap in chrome.panel()
    Change chart colors Modify Plotly trace parameters (marker_color, line_color)
    Move a component between pages Cut/paste the code block between view functions
    Change date range for a metric Modify WHERE start_time >= ... in the SQL
    Change credit price Search for * 4.0 or * 4 in data layer, replace
    Add a new waste pattern Add to generate_hidden_waste_data() in generate.py, regenerate
    Change TCO categories Edit cost_breakdown() SQL grouping in data layer
    Adjust forecast months Edit n_forecast in tco_monthly_trend_and_forecast()
